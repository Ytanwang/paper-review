# Paper Logic Review · 文献逻辑审查

**Peer-review-style logic audits of published papers** — does the argument chain close, does the evidence support the headline claim, and how strong a verb can you safely use when citing it?

对已发表论文的**同行式逻辑审查**：不是摘要，是审稿意见——论证是否闭环、证据是否支撑主张、结论是否落在数据允许的边界内。

**在线阅读：https://ytanwang.github.io/paper-review/**

## 为什么做这个

"这篇论文的结论能不能引？能引到什么强度？"是科研里每天都在发生、却几乎没有公开方法论的问题。文献综述和期刊俱乐部告诉你一篇论文"说了什么"，很少系统回答"它**证明了**什么"。本仓库把一套完整的审查协议和逐篇审查结果开源，让"批判性地读文献"变成可复用、可检验的公开实践——高影响因子不是通行证，每一条主张都要过证据这一关。

## v2.1 审查协议

每篇审查按同一条流水线执行：

```
① 生态位鉴定 → ② 闭环标尺 → ③ 三层探针 → ④ ERR 打标 → ⑤ 评级 + 补丁
      ↑                                                    │
      └──────────── 发现定位错误时回溯 ────────────────────┘
                                                           ↓
                          ⑥ 动词校准（三级清单） → ⑦ 资产回收（M 等级）
```

| 模块 | 回答的问题 |
|---|---|
| 生态位鉴定 | 论文想做什么、在证据链哪一环（描述 / 关联 / 机制 / 因果 / 转化），研究类型允许它下多强的结论 |
| 闭环标尺 | 把全文压成 A→B→C→D 主链，每步标注证据等级，判定闭环 / 断裂 / 超载 |
| 三层探针 | 只对承重主张（拆掉它标题级结论就站不住的主张）做：第一性原理层、演绎构建层、元认知审计层 |
| ERR 打标 | 五类错误定位：前提缺陷 / 因果链断裂 / 证据—主张不匹配 / 混杂与方法缺陷 / 元认知偏倚 |
| 评级 + 补丁 | A–D 六档总评级；每条 ERR 配具体到"补哪个分析、改哪句话"的修改补丁，按 P0→P2 排序 |
| 动词校准 | 三级动词清单：允许 / 谨慎 / 禁用——直接决定引用时能动多强的词 |
| 资产回收 | 数据、方法、实验、表达四类资产按 M1–M3 标注可复用性 |

**ERR 严重度与处置联动**：

| 严重度 | 定义 | 处置 |
|---|---|---|
| P0 | 不修则标题级主张不能成立 | 必须补实验 / 补分析，或降级主结论 |
| P1 | 削弱关键链条，但不推翻全文 | 补充分析、补对照、限制讨论 |
| P2 | 局部表述或方法透明度问题 | 改写、补说明、补引用 |

**动词天花板**：强因果（drive / mediate / cause / trigger）＞ 中因果（contribute to / promote / facilitate）＞ 安全描述（associate with / mark / characterize）。每篇审查明确给出当前证据下"允许的最高动词"——引用他人文献和写自己的稿件共用同一把尺。

## 复用这套协议

- 审查任何论文时按上面的流水线走：先定阅读目的，再显式写出 1–3 条承重主张，全套探针只对承重主张做。
- 判断 ERR 类型时先问：把证据换成理想版本，缺陷会自动消失吗？要换证据类型才能修好是因果链断裂，只缩小结论半径就能修好是证据—主张不匹配。
- 欢迎按协议写出你自己的审查，发 PR 收录进本仓库。

## 提交论文 / 反馈

想看某篇论文被审？[开一个 issue](https://github.com/Ytanwang/paper-review/issues) 告诉我论文链接和你想引用它的方式。发现打标或评级有争议，也欢迎开 issue 讨论——协议本身也应该被审。
